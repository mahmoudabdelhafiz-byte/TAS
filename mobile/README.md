# Yardsyncs mobile — the driver app (Flutter, Android and iPhone)

For truck drivers: sign in with the mobile number the trucking company registered (one-time code by SMS),
see upcoming appointments with the traffic light, show the gate code (QR) at the lane, press
"I am leaving now" when the truck sets off (the terminal re-checks the containers first), and follow
spoken directions to the container's block inside the terminal.
Arabic, English, Urdu and Hindi; right-to-left for Arabic and Urdu.

## Run

Requires Flutter 3.27 or later.

```bash
cd mobile
flutter create --platforms=android,ios --org com.yardsyncs --project-name yardsyncs_mobile .   # once: adds the platform folders
bash tool/configure_android.sh                                    # name, app id, permissions (location also in the background), text-to-speech
bash tool/configure_ios.sh                                        # on a Mac: name, bundle id, location texts, background modes, iOS 13
flutter pub get
flutter test
flutter run --dart-define=YARDSYNCS_API=http://10.0.2.2:5000      # Android emulator → API on your machine
flutter build apk --dart-define=YARDSYNCS_API=https://your-server  # release builds must use https
```

App identity: name **Yardsyncs mobile**, Android application id and iOS bundle id `com.yardsyncs.mobile`.
The platform folders (`android/`, `ios/`) are generated by `flutter create` and the configure scripts, and not yet
committed; they will be once icons and signing are settled. CI builds the Android APK and an unsigned iPhone build.

## Push notifications

Through Firebase Cloud Messaging (Firebase passes iPhone messages on to Apple's push service). One Firebase project
per installation:

1. Create a Firebase project; add an Android app (`com.yardsyncs.mobile`) and an iOS app (`com.yardsyncs.mobile`).
2. iPhone: in the Apple developer account create an APNs key and upload it to the Firebase project (Cloud Messaging
   settings); enable the Push Notifications capability for the bundle id.
3. Build the app with the Firebase values (no Firebase file is committed):
   `--dart-define=FIREBASE_PROJECT_ID=… --dart-define=FIREBASE_SENDER_ID=… --dart-define=FIREBASE_API_KEY=…
   --dart-define=FIREBASE_ANDROID_APP_ID=… --dart-define=FIREBASE_IOS_APP_ID=…`
4. Server: a service account with the "Firebase Cloud Messaging API Admin" role, in environment variables
   `Notifications__PushProvider=Fcm`, `Notifications__Fcm__ProjectId`, `Notifications__Fcm__ClientEmail`,
   `Notifications__Fcm__PrivateKey`.

Drivers signed in to the app then get messages by push instead of SMS; a push that can't be delivered (app removed)
goes by SMS instead. Without the Firebase values the app works as before and messages arrive by SMS.

## Screens

- **Sign in** — mobile number → 6-digit code by SMS. The session is bound to this phone; signing in on another phone signs this one out.
- **My appointments** — next first; day, hour (terminal time), terminal, traffic light, containers. Refreshes every minute and on pull.
- **Appointment** — reason behind the light, moves, company and truck, gate QR code (only while the appointment can still pass the gate), "I am leaving now".
- **Gate pass** — the QR changes every 30 seconds and is made on the phone from a secret received at sign-in, so it works without mobile data at the gate; signing in on another phone revokes it.
- **On the way** — after "I am leaving now" the position is sent about every minute, also with the phone locked or another app open (Android: foreground service with a "sharing your location" notification; iOS: background location). The terminal sees an arrival estimate, and the truck is checked in when it enters the pre-gate area; sharing stops there, when the trip ends, or on sign-out. Positions are only accepted while on the way.
- **In-gate ticket** — at gate-in the terminal reads the container's yard position from the TOS and the driver gets a push ("you are in, go to B2 (14.03.2)"); tapping it opens the ticket: appointment, truck, lane, time in and every stop with block / row / bay.
- **Where to go** — after gate-in: the next stop in large text (block, row / bay / tier), the yard map with the route, and the stop spoken in the driver's language (repeat and mute in the top bar). "Done here" waits while the truck is moving.

iOS (when the `ios/` folder is committed): `Info.plist` needs `NSLocationWhenInUseUsageDescription`,
`NSLocationAlwaysAndWhenInUseUsageDescription` and `UIBackgroundModes` → `location`.
